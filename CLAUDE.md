# Civil 3D MCP (UTNM fork) - working rules

Fork of Sacred-G/Civil3D-mcp, branch `utnm/alignment-from-ip`, remote https://github.com/amirclyde/Civil3D-mcp.git.
Owner: Amir (UTNM, Malaysia). Civil 3D 2026 (25.1), plugin loaded by NETLOAD.

## Standing rules
- Drive Civil 3D through the civil3d-mcp tools, never computer use (screen clicking) unless Amir says so for that task.
- Never `Database.SaveAs` a live drawing. Save with the MCP `civil3d_drawing save` (QSAVE) only.
- The engineer's design is not changed silently: "we only draw what is given and if it doesn't match, we highlight it".
  Slopes: the design ratio is the steepest allowed; anything steeper, or a bench whose fall reverses, is FLAGGED for
  remedial / extra protection, never hidden.
- Explain confusing design questions with a picture (sketch / section image), not only words.
- Amir pushes to GitHub himself. Commit locally when asked or at a clean checkpoint; never push.
- Junctions are a separate topic (Amir has a working workflow he will share) - do not design junction fixes.
- Mutating MCP actions need `civil3d_request_approval` first, then the same call with `approvalToken` and identical parameters.

## Build / reload routine
1. Close Civil 3D (the DLL is locked while it runs).
2. `powershell -NoProfile -ExecutionPolicy Bypass -File C:\Dev\Civil3D-mcp\scripts\rebuild-plugin.ps1`
   (npm run build -> build/, then dotnet build Release).
3. Open the drawing, NETLOAD `C:\Dev\Civil3D-mcp\Civil3D-MCP-Plugin\bin\Release\net8.0-windows\Civil3DMcpPlugin.dll`.
4. When TypeScript changed, restart the MCP server (in Claude Code: `/mcp` -> reconnect civil3d-mcp).

Checks without Civil 3D: `npx tsc --noEmit -p tsconfig.json`; bowtie kernel tests:
`dotnet run --project bowtie-kernel/BowtieKernel.Tests` (42 tests); subassembly flowchart checks:
`python subassemblies/UTNM_LaneDaylightClip/check_spread.py` (1440 cases).
